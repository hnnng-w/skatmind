## Delivered source and execution boundaries

### Manual guided and imported Historical Reviews

The explicit manual producers in `app_web/workflow_operations.py` observe the
genuine native invocation/execution from the existing private invocation-local
capture. Only a successfully published Historical execution reaches retention.
The shared guided executor itself does not save automatically. Analyze, imported
retrospective Position, direct Session Historical/Finalize and failed/superseded
manual candidates therefore do not become saved Historical Games.

Each New guided Review receives an independent private source identity. The exact
completed guided draft independently rebuilds the original Request; source-local
Game/Player keys use that source's namespace. Repeated raw
`frontend-historical-review` and Player placeholder IDs remain unchanged in original
Requests, Results and downloads. Names, seats and prefixes never establish origin.
Imported Historical input retains a separate shared-claim scope, even when it uses
those literal strings. Conflicting imported Game claims, including collisions with
known Match/Session Game identities, become explicit ambiguity exclusions rather
than duplicate coverage or arbitrary precedence.
Ordinary successive imports create independent saved sources. Only an explicit
**Reopen and correct Review** establishes imported correction mode. The existing
confirmed **Reset** is also available on an imported draft and preserves saved sources.

One optional manifest `historical_heads` entry binds each live source version to
its latest successful execution. Source, execution and head publish coherently in
one compare-and-swap transaction after immutable dependencies. Reopening and
correcting retain the logical source; changed input advances its exact version.
Changing only execution options retains the same input version and can retain
multiple genuine executions. The original guided options/draft belong to the
execution envelope; the source's normalized guided proof describes input only.

Confirmed deletion removes the live head and records the private retired identity.
Archived bytes do not restore membership, and a pending save cannot revive that
deleted identity. Historical evidence remains available under its original version
until separately previewed archive maintenance. Current head dependencies remain
protected. Drafts and unexecuted imports stay process-local. Guided entry still
emits normal completion; imported inputs keep all parser-supported endings and
continuations. There is no new shortened-ending editor or identity-management UI.

### Genuine native evidence and independent admission

Private codec-2 `historical_source`, `historical_review` and `match_historical`
objects retain exact source/version, Request/canonical Game, effective options and
supplied-option presence, source-time identities, external Statistics/reference,
actual Result, warnings, artifacts, original internal provenance and native exports.
Admission checks typed reconstruction, original invocation/options/external context,
source provenance, retained-stage linkage and final serialization. It independently
reconciles canonical Game, chronological legal play, Trick ownership, source cutoff,
requested attachment presence, actual Decision identities, Immediate settings/counts
and source-time Profile bindings.

Normal and non-proof shortened outcomes reuse pure rule/settlement derivation.
Continuation validation is pure source reconstruction. Proof-bearing endings retain
the original proof; admission independently checks their original point accounting,
cutoff and exposure/Claim preparation/assignment relationships without executing a
proof solver. Matching/rehashed digests alone do not admit contradictory outcomes or
materializations. This validates retained evidence relationships, not historical
truth, authorship or a new solver proof.

Historical provenance is repetitive and can exceed 16 MiB uncompressed for a
30-Decision review. The private `zlib-json-v1` native encoding uses only the standard
library, with bounded decompression, exact expanded length/digest and complete-stream
checks. Expanded tuples are bounded at 128 MiB. Stored source/envelope objects retain
the existing 16-MiB bound, global 512-MiB object quota and 2,048-per-evidence-class
limit. Native download bytes are retained/reconciled exactly, without compression or
identifier rewriting at the HTTP boundary.

The native external-options decoder preserves JSON array semantics through the
closed typed sequence codec. It does not equate missing options with supplied
defaults or consult today's Profile to reconstruct original external context.
Base Historical execution contributes its actual outcome/coverage; absent optional
Review/Coaching never produces invented assessed Decisions.

### Managed Match Historical publication

`match_historical_analysis.py` optionally observes its actual original Application
invocation/execution. `capture_web/analysis.py` publishes that observation only after
the existing Report guard succeeds. The unified managed Match caller captures the
original saved Workspace before execution and retains it through its existing
owner/attempt/source/selection guards and save-only retry mechanism.

Admission rebuilds the selected Game's strict Historical materialization, Match
options and eligible external statistics without analysis. Findings attach to the
existing Match Game. They create no manual Review head, duplicate Game, ordinary
Decision Report, Teacher label, Tactical qualification or recurring focus. Standalone
Capture and non-executing materialization keep their existing behavior.

## Generation, lifetime and delivery

Historical-capable generations use explicit object codec **4**, producer
`automatic_historical_preparation`, recipe version **1**, with an exact source and
evidence ledger and complete family fingerprints. Codec-2 Match and codec-3
Match/Session recipes retain their meanings and reject Historical execution
selection. Unsupported future codecs/recipes stay unsupported. Malformed ledgers
produce controlled admission/service/HTTP recovery rather than accidental 500s.

One automatic generation composes the existing Match slice, native Session family
and separate Historical per-game evidence. Historical sources do not enter the ten
Match downloads. Match membership revision/basis survives Historical-only changes
and cleanup retiring **both** mixed descriptors. Explicit restart reconstruction
preserves all ten Match bytes when Match inputs are unchanged. Exclusions, ambiguity,
stale/deleted classifications, current-plus-previous retention and independent manual
collection ownership remain explicit.

Saving failure retains the successful process-local execution and truthful status.
The bounded pending save retains the original owner, state/attempt, source, candidate
and execution. Retry publishes those values only, with zero evaluation. Manifest
replacement is authoritative even when return/synchronization fails. Neither an old
attempt nor cleanup rolls back or overwrites a newer successful publication.

The bounded exact-byte receipt additionally retains admitted typed values. It still
checks complete current manifest, storage inventory, live Match/Session bytes and
saved Historical heads. Its existing 64-object/candidate and 16-MiB stored-byte bounds
are supplemented by a 128-MiB expanded-native bound; larger captures use strict
admission. Each owning scope retains one current receipt, not a TTL cache. Old views
retain bindings rather than accumulating additional typed receipt caches. Final HTML,
native/enhanced language return and downloads revalidate original owner, attempt,
view, source, manifest, inventory and generation. Reader pins span native downloads.

Passive viewing, language switching, downloads, Update and explicit reconstruction
execute no new card analysis. Preparation may replay/reconstruct accepted inputs and
derive existing summaries. Recording writes, archive publication, Profile saves and
fixture analysis are separate operations.
